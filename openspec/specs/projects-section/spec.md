# projects-section Specification

## Purpose

定义项目展示区的行为：卡片式网格布局、卡片内容构成（截图/名称/简介/GitHub 链接）、最小项目数量、悬浮微特效与内容可替换性。本能力承接 content-sections 中项目 section 的内容行为。

## Requirements

### Requirement: 卡片网格布局

项目区 SHALL 以响应式卡片网格呈现项目：窄视口单列纵向堆叠、中宽视口两列、桌面视口三列以上（依视口宽度自动适配），卡片间距统一、同一行卡片等高对齐。网格 SHALL 保证页面总高度仍大于首屏（不破坏「可产生离顶滚动状态」的能力）。

#### Scenario: 桌面网格呈现

- **WHEN** 用户在桌面视口打开项目区
- **THEN** 项目卡片以多列网格排列，同行卡片等高、间距一致，无错位或溢出

#### Scenario: 窄屏单列堆叠

- **WHEN** 用户在移动端窄屏（约 360px 级别）查看项目区
- **THEN** 卡片退化为单列纵向堆叠，不错位、不横向溢出，内容完整可读

#### Scenario: 页面高度不塌陷

- **WHEN** 项目卡片按内容常量渲染完成
- **THEN** 页面总高度仍大于首屏（项目区自身不低于合理最小高度），滚动到底仍可产生离顶状态

### Requirement: 项目卡片内容

每张项目卡片 SHALL 呈现四项信息：项目截图、项目名称、一句简介、GitHub 链接。项目数据 SHALL 至少包含 4 条记录（由内容常量提供，实际展示数量随数据增减）。截图缺失时 SHALL 以渐变占位图块呈现（不得出现空窗或破图）。GitHub 链接 SHALL 在新窗口/新标签页打开，并 SHALL 不暴露反打（opener）漏洞；图片 SHALL 使用原生 lazy loading。

#### Scenario: 卡片四要素齐全

- **WHEN** 内容常量提供完整数据且页面为默认构建
- **THEN** 每张卡片同时展示截图（或其渐变占位块）、名称、简介与 GitHub 链接，无空文本元素

#### Scenario: GitHub 链接新窗口跳转

- **WHEN** 用户点击任一卡片的 GitHub 链接
- **THEN** 仓库在新的标签页/窗口打开，原页面保持当前滚动位置不丢失

#### Scenario: 数据替换即生效

- **WHEN** 站点所有者替换内容常量中的项目数据（增删改）
- **THEN** 卡片数量与内容随之变化，无需修改组件逻辑

### Requirement: 悬浮微特效

鼠标悬浮于项目卡片 SHALL 触发 CSS 微特效（如轻微抬升/缩放/投影增强），过渡平滑且移出后恢复原状；微特效 SHALL 为纯 CSS 实现，不引入 JS 逐帧动画。在无 hover 能力的触屏环境 SHALL 不产生残留悬浮状态。

#### Scenario: 悬浮微特效与还原

- **WHEN** 用户鼠标悬浮到卡片再移出
- **THEN** 悬浮期间卡片出现平滑微特效，移出后恢复原状、无闪烁或状态残留

#### Scenario: 触屏环境降级

- **WHEN** 设备不支持 hover（触屏）
- **THEN** 卡片外观保持默认态且链接可正常点击，不出现永远处于悬浮态的卡片
